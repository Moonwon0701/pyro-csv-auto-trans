# 불꽃쇼 CSV 자동 정리 (Pyro CSV Organizer)

불꽃쇼 디자인 프로그램에서 Export한 CSV를 **현장용 Excel**로 자동 정리하는 데스크톱 프로그램입니다.

| 단계 | 화면 | 하는 일 |
|---|---|---|
| 1 | **① 치구 배치** | 원본 CSV의 단발(S-*)을 치구·모듈로 나눔. 무대 지도 → 위치 확대도로 어느 칸에 어떤 약을 몇 도로 꽂는지 확인 |
| 1 → 2 | **② 주소 매기기** | FM-A 주소(예: `1F0`)를 위치별로 겹치지 않게 채움. 단발은 ①에서 정한 치구 순서 그대로 |
| 2 → 3 | **③ 시트 정리** | 주소가 매겨진 CSV를 LAYOUT + 치구 배치도 + Control × 타상/연발/단발 시트로 정리한 Excel 생성 |

화면 위의 `① › ② › ③` 순서대로 진행하고, 아래 “→” 버튼으로 다음 단계, “←” 버튼으로 이전 단계로 갑니다. 앱은 ①부터 시작합니다. 이미 주소가 매겨진 CSV는 ③에 바로 넣어도 됩니다.

- Control별 × **타상 / 연발 / 단발** 시트 자동 분리 (FC-01, FC-02 … 개수 제한 없음)
- POS 표준화: 타상만 `3P/4P/5P/6P → P`로 같은 번호끼리 합침. 연발·단발은 `C-01`, `CF-01`, `S-01`, `GI-01`처럼 원래 POS 그대로 열을 만들고 접두어마다 표를 따로 만들어 한 시트 안에서 위아래로 쌓음 (`C-01…C-05` 표 아래에 `CF-01…CF-05` 표, 단발은 S → GI → GO …) (열 자동 확장)
- **HH + MM + SS + FF + Effect Description** 이 같은 행을 한 줄(Cue)로 병합
- 주소: `ADDR` 우선, 없으면 `MODULE-PIN` (예: 12-29)
- 처음 보는 Prefix(예: `FX-01`)는 추측하지 않고 사용자에게 분류를 물어봄
- 같은 위치에 주소가 여러 개면 **모두 보존**하고 노란색으로 표시

## 디자이너용: 설치하기

[**최신 버전 다운로드 (Releases)**](https://github.com/Moonwon0701/pyro-csv-auto-trans/releases/latest)

### Windows
1. `PyroCSV-Setup-x.y.z.exe`를 받습니다.
   - Edge에서 "일반적으로 다운로드되지 않습니다"라고 나오면 다운로드 목록에서 파일 옆 **… → 유지** → **자세히 표시 → 그래도 유지**를 누릅니다. (Chrome은 **다운로드 목록 → 계속**.)
2. 받은 파일을 실행합니다. "Windows의 PC 보호" 창이 뜨면 **추가 정보 → 실행**을 누릅니다. (코드서명이 없는 사내 프로그램이라 뜨는 창입니다.)
3. 바탕화면의 **불꽃쇼 CSV 자동 정리** 아이콘으로 실행합니다. 새 버전이 나오면 자동으로 받아서 "재시작해서 적용" 버튼을 띄웁니다.

### Mac
1. `PyroCSV-x.y.z-mac.dmg`를 받아서 열고 앱을 **응용 프로그램** 폴더로 끌어다 놓습니다.
2. 처음 실행할 때는 앱을 **우클릭(Control+클릭) → 열기 → 열기**로 실행합니다. (한 번만 하면 됩니다.)
   - "손상되었기 때문에 열 수 없습니다"라는 메시지가 나오면 터미널에서 `xattr -cr "/Applications/Pyro CSV Organizer.app"`를 실행한 뒤 다시 엽니다.
3. 새 버전이 나오면 앱 상단에 알림이 뜹니다. 다운로드 페이지에서 새 dmg를 받아 덮어쓰면 됩니다.

## 사용법

처음 실행하면 사용법 안내가 뜹니다. 오른쪽 위 **사용법** 버튼으로 다시 볼 수 있어요. 마지막 장의 **샘플로 따라하기**를 누르면 앱에 들어 있는 가상 샘플 CSV로 ② → ③ → Excel 생성까지 단계별 안내를 받으며 연습할 수 있습니다. 튜토리얼 중에는 Rule이 저장되지 않습니다.

### ① 치구 배치 (원본 CSV → 단발을 치구·모듈로)

혜원 2026-09-30: "치구 배치 후에 주소 배정". 치구(단발 거치대)는 4×5칸(가로 5칸 × 4줄)이고 모든 칸을 바닥 기준 30°까지 눕힐 수 있습니다. 행사 전에 치구마다 모듈을 미리 결선해 가므로, 모듈이 치구 두 개에 걸치면 한쪽은 현장에서 결선해야 합니다.

1. 디자인 프로그램에서 뽑은 원본 CSV를 창에 끌어다 놓습니다.
   - **처음 보는 위치 접두어**(예: `FX-01`)가 있으면 빨간 상자에서 타상/연발/단발/제외를 먼저 고릅니다. 모두 골라야 다음 단계로 갈 수 있습니다. “Rule 저장”이 켜져 있으면 넘어갈 때 내 PC Rule로 저장되고, 끄면 이번 작업(③까지)에만 쓰입니다.
2. 치구 대상 위치(기본 `S-*`, Rule 관리의 **치구** 열로 바꿀 수 있음)의 약을 수직에서 기운 방향 순서로 늘어놓습니다. 같은 위치의 cake은 치구에 넣지 않습니다.
3. 모듈은 16핀·약 20발을 넘지 않게 나누고, 이어지는 모듈끼리 20발 안에서 한 치구로 묶습니다. 모듈이 치구를 넘지 않으므로 현장 결선이 없습니다. 왼쪽 **치구 설정**에서 바꿀 수 있습니다.
   - **우선순위**: 모듈 수 먼저(기본, 과거 관행) / 치구 수 먼저
   - **모듈이 치구 두 개에 걸쳐도 됨**: 치구는 더 줄지만 걸친 핀은 현장 결선 대상으로 표시됩니다.
4. 치구 안에서는 약을 각도순으로 줄마다 번갈아 나눠, 줄마다 왼쪽 끝이 가장 왼쪽으로·오른쪽 끝이 가장 오른쪽으로 눕게 꽂습니다.
5. 직렬(한 핀에 약 여러 발)은 TILT의 발별 각도(`-75--45-75` = -75, -45, 75)로 칸을 나눕니다. 엑셀에서 열었다 저장해 `-40-40`이 `-80`으로 계산돼 버린 CSV는 평균 각도로 추정하고 경고합니다. **디자인 프로그램에서 뽑은 원본 CSV를 쓰세요.**
6. **무대 지도**(레이아웃처럼 단발 위치를 가로로)에서 위치를 누르면 **확대도**: 관객석에서 본 부채꼴(선 하나 = 약 하나, 괄호 = 치구·모듈)과, 치구를 누르면 칸 배치표(줄 × 칸, 칸마다 핀 순서 `M1-3` = 1번째 모듈 3번 핀, 각도 `↖-30°`·`↑90°`·`75°↗`, TILT와 같은 바닥 기준이라 90° = 수직). 실제 주소는 ②에서 이 순서대로 붙습니다.
7. **② 주소 매기기 →**.

타상은 치구 규칙과 상관없습니다. 연발은 규칙이 정해지면 추가합니다.

### ② 주소 매기기 (→ 주소 매긴 CSV)

1. ①에서 넘어온 원본의 위치(POS)마다 주소 범위가 자동으로 제안됩니다. (단발을 치구에 꽂지 않는 쇼면 원본 CSV를 여기에 바로 넣어도 됩니다.)
   - Control마다 모듈 10부터 시작합니다 (010처럼 0으로 시작하는 주소는 엑셀에서 앞자리 0이 사라지므로). 화면에서 바꿀 수 있습니다.
   - 위치마다 새 모듈에서 시작해서, 필요한 핀 수만큼 이어서 잡습니다.
   - 모듈 00과 xE(0E, 1E…)는 건너뜁니다.
   - 이미 주소가 있는 행은 그대로 두고, 그 주소는 다시 쓰지 않습니다.
3. 필요하면 범위를 직접 고칩니다. 예: `310` (여기서부터), `310-33F`, `01F-01F, 110` (여러 범위를 순서대로).
4. 위치 안의 순서를 고릅니다 (타상·연발).
   - **효과순**(기본): 같은 효과끼리 모은 뒤 시간순
   - **시간순**
   - 단발(치구 대상)은 이 설정과 상관없이 **①에서 정한 치구 순서**로 매깁니다. 이미 주소가 있던 단발 위치는 그대로 둡니다.
5. **주소 CSV 저장**을 누르면 `원본이름_ADDR.csv`로 저장됩니다. 원본과 같은 인코딩과 컬럼을 유지하므로 디자인 프로그램에 다시 넣을 수 있습니다.
6. **③ 시트 정리 →**를 누르면 ③ 화면으로 넘어갑니다. **← ① 치구 배치**로 돌아가도 두 화면의 파일·설정은 그대로 남습니다.

### ③ 시트 정리 (주소 매긴 CSV → 현장용 Excel)

1. CSV 파일을 창에 **끌어다 놓습니다**. 클릭해서 선택해도 됩니다.
2. 왼쪽에서 분석 결과를 확인합니다: Control, 주소 방식, Rule 적용 결과, 경고.
   - ①을 거쳐 왔으면 접두어 분류는 이미 끝나 있습니다. ③에 파일을 바로 넣었는데 **처음 보는 위치 접두어**가 있으면 여기서 빨간 상자로 고릅니다. "Rule 저장"에 체크하면 다음부터 자동으로 처리됩니다.
3. 오른쪽 미리보기에서 시트를 확인한 뒤 **Excel 생성**을 누릅니다. 결과는 `원본파일명_정리.xlsx`로 저장됩니다.

| 표시 | 의미 |
|---|---|
| 노란 셀 | 같은 Cue·같은 위치에 주소가 여러 개 (모두 보존) |
| 주황 셀 `주소없음` | 해당 위치는 쓰였지만 ADDR/MODULE-PIN 값이 없음 |
| `미배치 POS` 열 | POS 형식을 인식하지 못했지만 TYPE으로 분류된 행 (원본 값 보존) |
| `미분류` 시트 | POS와 TYPE 모두로 분류할 수 없는 행의 원본 |

- 맨 앞에 **LAYOUT** 시트가 들어갑니다. 서식은 기존 LAYOUT 양식(2026-09 퐁피두)과 같습니다: 위치마다 쓰는 모듈(`36F` = 모듈 36을 F핀까지, 타상은 검은 칸에 `3FF (19)` = 19발), 오른쪽에 인치·발수·모듈수량(단발 줄의 발수 칸에는 치구 수). 거리(`<<------ M------>>`)와 타상 각도 칸은 CSV에 없어 비워 둡니다.
- 단발 주소가 치구 순서로 매겨진 파일이면 **치구 배치도** 시트도 들어갑니다 (치구마다 줄×칸 격자에 주소·각도·효과).
- 옵션의 **원본 데이터 시트 포함**을 켜면 맨 앞 시트에 (주소 매긴) 원본 CSV 전체를 넣습니다.
- 옵션의 **행 순서**에서 제품명순(기본, 같은 효과끼리 모아서 시간순, 기존 수작업 정리 방식)과 시간순을 고를 수 있습니다.
- CUE는 원본 CUE 번호입니다(병합된 그룹은 첫 행의 CUE). 마지막 열의 **NOTE**는 현장 메모용 빈 칸입니다.
- 같은 주소를 서로 다른 위치가 함께 쓰면 경고합니다.

## 관리자용: 공용 Rule 관리

모든 PC는 시작할 때 이 저장소의 [`rules/rules.json`](rules/rules.json)을 받아서 사용합니다. 오프라인이면 마지막으로 받은 사본을 씁니다.

- **직접 수정**: GitHub에서 `rules/rules.json`을 편집하고 Commit하면, 각 PC에서 앱을 다시 켜거나 "Rule 관리 → 최신 공용 Rule 받기"를 누를 때 반영됩니다.
- **디자이너가 올린 Rule**: 디자이너가 "Rule 관리 → 공용 Rule로 올리기"를 누르면, 공용과 다른 내 PC Rule이 채워진 `[Rule 요청]` 이슈 작성 페이지가 열립니다. GitHub 계정(무료)으로 로그인해 Submit하면 [GitHub Actions](.github/workflows/rule-request.yml)가 내용을 검사하고 `rules.json`에 Prefix 단위로 합쳐 Commit한 뒤 이슈를 닫습니다. 편집 권한은 필요 없습니다.
  - [`rules/contributors.txt`](rules/contributors.txt)에 아이디가 있는 디자이너와 저장소 관리자의 요청은 **바로 반영**됩니다.
  - 그 밖의 사람이 올린 요청은 "관리자 확인 대기" 댓글이 달립니다. 내용이 맞으면 이슈에 **`승인` 라벨**을 붙이면 반영됩니다. 틀리면 이슈를 닫으면 됩니다.

```jsonc
// positionRules 항목 예시
{ "pattern": "FX-*", "category": "단발", "output_prefix": "S", "active": true, "source": "user" }
// category: "타상" | "연발" | "단발" | "제외"
// jig: true면 ② 치구 배치 대상 (단발만). 없으면 S-*만 대상
```

## 개발

```bash
npm install
npm run dev        # 개발 모드 실행
npm test           # 변환 엔진 테스트 (Spec의 T01~T12 포함)
npm run dist:win   # Windows 설치파일 → dist/
```

- `src/engine/`: 변환 엔진 (순수 TypeScript, Electron 의존성 없음)
- `src/main/`: Electron main (파일 입출력, Rule 동기화, 업데이트)
- `src/renderer/`: 화면 (React)

### 새 버전 배포

```bash
npm version patch          # package.json 버전 올림 + 태그 생성
git push --follow-tags     # GitHub Actions가 Windows/Mac 설치파일을 만들어 Release에 올림
```

### 실제 샘플로 회귀 테스트

고객 CSV와 결과 Excel은 저장소에 올리지 않습니다. `samples/` 폴더(git 제외)에 둡니다.

1. `samples/`에 원본 CSV와 정리 완료 Excel을 넣습니다.
2. `py scripts/xlsx_to_expected.py "samples/결과.xlsx" "samples/원본.csv"`를 실행하면 `samples/expected/원본.json`이 만들어집니다.
3. 필요하면 `samples/expected/원본.meta.json`을 작성합니다. 예: `{ "resolutions": { "5S": "타상" }, "ordered": true }`
4. `npm test`: 시트, 그룹 수, 셀 값이 기대 결과와 같은지 확인합니다.
